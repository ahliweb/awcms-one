feat(commerce): returns, refunds and exchanges with inventory/payment compensation (Issue #287, epic #281)

New tables `awcms_commerce_returns`, `awcms_commerce_return_lines`, `awcms_commerce_refunds`, `awcms_commerce_refund_compensations` (`sql/994` schema + triggers + REVOKEs, `sql/995` integration, `sql/996` five permissions, `sql/997` worker purge grants). Database-level guarantees: `BEFORE INSERT` on return lines locks the order item and refuses Σ quantity above the quantity sold; `BEFORE INSERT/UPDATE` on refunds caps active legs + booked reversals at the payment (under the order lock); shipping refunded is capped at the shipping charged; return lines and compensations are append-only; returns move only `open → completed` and gain their exchange link once; refunds move only along `pending → processing → succeeded | failed` and never leave `succeeded`. `sql/995` also adds a trigger capping Σ succeeded payment reversals at the payment, `awcms_commerce_order_events.return_id` (nullable composite FK, `ON DELETE SET NULL (return_id)`), `source_type = 'refund'` on the loyalty ledger (the "one reversal per earn" unique index narrowed to non-refund reversals) and `awcms_commerce_affiliate_commissions.adjusted_amount`.

Application: `application/return-directory.ts` (create / later refund / exchange link / reconcile), `refund-settlement.ts` (one settlement transaction: payment-ledger reversal via `recordPaymentReversal`, store-credit load/issue, state move, loyalty + affiliate compensation, completion, audit, event; every refusal decided before the first write by `checkRefundSettlement`), `refund-execution.ts` (claim → provider with no transaction open → record; offline settlement), `return-inventory-port.ts` (the single stock count behind a port for #282), `domain/returns.ts` (per-unit cent decomposition, largest-remainder discount allocation, refund planning, validators). `PaymentGatewayProvider.refund?` is a new optional port method (log + Midtrans `refund/online/direct`). The loyalty ledger gains `reverseEarnForRefund` (proportional, cumulative, `reversal:refund:{id}`); the affiliate directory gains `adjustAffiliateCommissionForRefund`; the sales-report sinks, rebuild and control totals route `returned` order-event rows through `computeSalesReturn*` and net earlier returns out of a later cancellation.

New endpoints (all behind the `returns` feature flag, default OFF → `409 FEATURE_DISABLED`; every mutation requires `Idempotency-Key`):

- `GET`/`POST /api/v1/commerce/orders/{id}/returns` (`commerce.returns.{read,create}`; a `refund` also `commerce.refunds.create` + `commerce.payments.revoke`)
- `GET /api/v1/commerce/returns`, `GET .../returns/{id}`, `GET .../returns/reconcile` (`commerce.refunds.read`)
- `POST .../returns/{id}/refunds`, `POST .../returns/{id}/refunds/{refundId}/execute` (`commerce.refunds.create` + `commerce.payments.revoke`; `502 PROVIDER_REFUND_FAILED`, `503 GATEWAY_UNAVAILABLE`), `POST .../refunds/{refundId}/offline` (`commerce.refunds_offline.approve` + `commerce.payments.revoke`, mandatory reason)
- `POST .../returns/{id}/exchange-order` (`commerce.returns.create`)

New errors include `409 RETURN_QUANTITY_EXCEEDED`, `ORDER_NOT_RETURNABLE`, `REFUND_EXCEEDS_REFUNDABLE`, `REFUND_NOT_REFUNDABLE`, `SHIPPING_REFUND_EXCEEDED`, `STORE_CREDIT_UNAVAILABLE`, `NOTHING_TO_REFUND`, `NOT_AN_EXCHANGE`, `EXCHANGE_ALREADY_LINKED`, `EXCHANGE_ORDER_INVALID`. Events `awcms.commerce.return.recorded` and `awcms.commerce.refund.settled` on the return aggregate (registered in `module.ts`, the event-type registry and AsyncAPI). `dataLifecycle`/`subjectData` descriptors for all four tables (`domain/returns-lifecycle.ts`). Admin: the order detail's "Returns and refunds" panel and wizard (`components/CommerceReturnsPanel.astro`, `lib/ui/commerce-returns-client.ts`), a "Returns, refunds and exchanges" toggle in the commerce Features section.
