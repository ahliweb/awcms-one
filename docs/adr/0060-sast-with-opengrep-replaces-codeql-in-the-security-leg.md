# ADR-0060 — SAST with OpenGrep replaces CodeQL in the `local-ci/security` leg

- **Status:** Accepted
- **Date:** 28 November 2026
- **Decision maker:** ahliweb (owner decision of 27 November 2026, internal cross-portfolio standard DL-098; owner instruction of 28 November 2026 to apply it here)
- **Related:** issue [#603](https://github.com/ahliweb/awcms-one/issues/603); [ADR-0021](0021-zero-github-actions-local-ci-with-exact-sha-statuses.md) (local CI; its D7 describes the CodeQL leg and is superseded by this ADR for the SAST part only, and its rejected alternative "Semgrep-only for the security leg" is revisited here); [ADR-0018](0018-awcms-one-is-a-template-with-build-profiles-and-an-idempotent-init.md) and [ADR-0024](0024-awcms-one-is-template-only-derived-apps-own-their-backend.md) (this repository is a template; derived repositories own their own CI)

## Context

The `local-ci/security` leg ran the CodeQL CLI. The CodeQL CLI is free to use on public repositories, which this one is, but GitHub's CodeQL terms forbid it on codebases that are not open source and in CI without a paid GitHub Advanced Security licence. A repository created from this template is usually private, and it inherits `tools/ci/` as it is. The owner chose one SAST path for every repository of the portfolio, public ones included: CodeQL is not run anywhere, in a workflow, on a server or on a workstation. Since then the leg cannot be run at all, so `local-ci/security`, a required context on `main`, cannot be posted green for any PR.

ADR-0021 rejected a Semgrep-only security leg because the community rules do not reach CodeQL's dataflow depth. That trade-off is now forced the other way: there is no licensed CodeQL path left, and a pattern/taint engine with a pinned, redistributable rule set is what remains.

## Decision

- **D1.** The leg runs three checks: OpenGrep, gitleaks (digest-pinned image, `tools/ci/gitleaks.toml`, unchanged) and `bun audit` (threshold and `tools/ci/dependency-audit-exceptions.json` unchanged). The leg name and status context stay `local-ci/security`, so branch protection does not change.
- **D2.** OpenGrep `v2.1.0`, asset `opengrep_linux_x86`, pinned by sha256 `d6a68a84c01a3d8ee933f60847decf1b4d0fd7791a26833b32b95922baf28974` (`tools/ci/lib/opengrep-cli.ts`). It is downloaded to a `.part` file, verified, then renamed; a cached binary is re-verified before every use; a mismatch fails the leg.
- **D3.** Rules are a vendored copy of `opengrep/opengrep-rules` at commit `f1d2b562b414783763fd02a6ed2736eaed622efa`: every `.yaml` and `.yml` rule under `javascript/` and `typescript/` (203 files, test fixtures excluded) plus the upstream `LICENSE`, under `tools/ci/sast/rules/`, with the git blob id of each file in `tools/ci/sast/rules.lock`. The workflow rules (`yaml/github-actions/`) are not vendored, because this repository has no root `.github/workflows/` (ADR-0021). Semgrep Registry rules (`p/...`) and `semgrep/semgrep-rules` after 2024-12-13 are not used. The rules directory keeps its own licence (Commons Clause over LGPL-2.1), stated in `tools/ci/sast/rules/README.md`; it is not under the repository's MIT licence.
- **D4.** The gate fails only on an ERROR-severity finding that is not in `tools/ci/security-baseline.json` (matched by rule id and path); WARNING and INFO findings are counted in the evidence report, not gated. The baseline only shrinks. Its adoption content comes from one full scan of the tree, run once on the CI server with `bun tools/ci/cli/sast-baseline.ts`, which refuses to run unless the ADOPTION-BASELINE-PENDING marker exists and the baseline is empty, writes every ERROR finding and deletes the marker. While the marker exists the leg fails closed. `BASELINE_CEILING` in `tests/local-ci-baseline.test.mjs` is set to the generated count in the same commit; raising it later is a reviewed decision with a reason per entry, never a script. An agent never adds an entry to pass its own PR. The CodeQL-era entries (CodeQL rule ids, which no OpenGrep finding can match) are removed; their reasoning stays in `SECURITY.md`.
- **D5.** The scan runs offline after the pinned download: `--disable-version-check`, the vendored rules only, `SEMGREP_SEND_METRICS=off` (OpenGrep `v2.1.0` rejects a `--metrics` option, so none is passed), and `--jobs` from `CI_LOKAL_CPUS` (default 5). The excludes are the former `.github/codeql/codeql-config.yml` `paths-ignore` plus the rules directory; `apps/cms/**` source stays in scope. The JSON report is the leg's evidence; results are not uploaded to GitHub code scanning. The generator's report is an intermediate and is removed in a `finally`.
- **D6.** CodeQL is removed: `.github/codeql/codeql-config.yml`, the CodeQL CLI downloader (the `codeql-cli.ts` module under `tools/ci/lib/`, with its version, checksum and query-pack pins), the SARIF parser (`sarif.ts` in the same directory), the SARIF upload and the `--upload-sarif` option of `bun run ci`. The upstream subtree copies under `apps/cms/` (its `.github/workflows/codeql.yml`, `.github/codeql/` and CodeQL triage skill) are not run here and are not edited; they follow upstream.

## Consequences

- **Blind spots versus CodeQL, accepted:** pattern and taint matching on the syntax tree instead of whole-program dataflow, so fewer inter-procedural flows are found and a clean run is weaker evidence; a frozen rule snapshot that changes only by deliberate bump; `.astro` files are not scanned (as before); no alert lifecycle and no Security-tab view; only ERROR findings gate.
- Until the adoption baseline is generated and committed, `local-ci/security` is red by design. The PR that brings this ADR merges only with that baseline.
- Removing any CodeQL-named required context or code-scanning setting from repository settings is an owner action, not part of this change; `main` requires `local-ci/security`, whose name does not change.
- A bump of the OpenGrep version or of the rules commit is its own change: verify the new digest against the release, re-vendor and regenerate `rules.lock`, re-check the rules licence, re-run the leg, and handle any new ERROR finding through the baseline review, not by regenerating the baseline.
- **Rollback:** revert the PR that introduced this ADR. That restores the CodeQL leg, which the owner's decision does not allow to run, so a rollback is for diagnosis only.
