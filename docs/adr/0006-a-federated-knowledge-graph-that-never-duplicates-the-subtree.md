# ADR-0006 — A federated knowledge graph: root-owned, code-only, never duplicating `apps/cms`'s own

- **Status:** Accepted
- **Date:** 15 September 2026
- **Decision maker:** ahliweb
- **Related:** [issue #11](https://github.com/ahliweb/awcms-one/issues/11) (this workflow's own scope, and the "Recommended architecture" it argues from); [`knowledge/README.md`](../../knowledge/README.md) (the full mechanism — this ADR restates the decision, not the mechanism, to avoid the two drifting apart); [ADR-0001](0001-git-subtree-with-full-history-for-apps-cms.md) (why `apps/cms` is never hand-edited from this repository)

## Context

`apps/cms` already carries its own Graphify graph, its own `.graphifyignore`, and its own gate (`apps/cms/scripts/graph-artifacts-check.ts`) — inherited whole from `ahliweb/awcms` via the subtree embed. `awcms-one` is not a bare copy of that repository: it is a Bun monorepo where root-owned workspaces (`apps/storefront`, `packages/*`, `tools/`, `docs/`, `knowledge/` itself) have no graph coverage of their own, and `README.md` said so plainly — `audit:graf` was withheld until there was a real corpus for it to guard, rather than ported early as a check that would pass trivially forever.

The tempting shortcut — extract one graph over the whole repository, `apps/cms` included — was considered and rejected before it was tried: `apps/cms`'s own graph already has roughly 12,700 nodes. Re-extracting that tree at the root would build a second, competing copy of the same code's graph, committed here, growing every time either side grows, with two authorities now able to disagree about the same file.

## Decision

Two graphs, not one, kept deliberately separate:

- **`graphify-out/graph.json`** — this workspace's own, root-owned graph, built by `graphify extract . --code-only` with `.graphifyignore` excluding `apps/cms/**` entirely. Measured at 396 nodes, 599 edges, 25 communities as of this writing — two orders of magnitude smaller than `apps/cms`'s own, because it covers only what this repository actually owns.
- **`apps/cms/graphify-out/graph.json`** — untouched, read-only from this repository's point of view, `awcms`'s own artefact, arriving here only through the ordinary subtree sync (ADR-0001), never hand-edited or regenerated by anything under `tools/` or `packages/gerbang/`.

**Extraction is code-only by default, and this is a security property, not a performance one:** `--code-only` performs local AST extraction with no LLM call of any kind, for any file, ever, in this workflow's default path — verified directly (neither `GEMINI_API_KEY` nor `GOOGLE_API_KEY` is set on the machine this was built on, and `graphify`'s code-only mode reads no other provider key at all), and `graphify-out/cost.json` records `0`/`0` tokens across every run, printed by `audit:graf` on every check so a nonzero figure would be visible rather than silent. Community naming (`graphify cluster-only .`) is the same: with no LLM backend configured it falls back to deterministic, free hub-based naming, and the 25 communities this graph carries were then given human-chosen, plain-language names by hand — the same discipline `apps/cms`'s own graph documents and its own gate enforces.

**A federated, combined view exists, but only on demand and never committed.** `bun run knowledge:graph:combine` merges this graph with `apps/cms`'s own into `graphify-out/combined/graph.json` for genuinely cross-workspace questions ("what in `apps/storefront` depends on something in `apps/cms`") — gitignored, regenerated fresh each time, never a substitute for either graph on its own territory. An earlier draft of this workflow considered committing that combined file so a fresh clone would not need `graphify` installed to query it; measured against the real sizes above, the combined graph runs to tens of megabytes — essentially a second, growing copy of `apps/cms`'s own graph, checked in at the root, which is exactly the duplication this decision exists to refuse. The Obsidian export (`bun run knowledge:obsidian:export`) follows the same rule for notes instead of JSON: it stages and validates only the root graph, never the combined one, for the identical reason — exporting the combined graph would write one note per node, nearly 13,000 of them, almost all restating `apps/cms`'s own content, into a directory this repository commits.

Full mechanism, the tracked/untracked artefact table, the toolchain, and the nine-item security-and-privacy table are documented once, in [`knowledge/README.md`](../../knowledge/README.md); this ADR does not duplicate them.

## Consequences

- `bun run audit:graf` runs in CI unconditionally (it reads only already-committed artefacts, needs no network and no `graphify` binary) and checks, among other things, that no node in the tracked root graph has a `source_file` under `apps/cms/` — the mechanical proof that no accidental duplicate extraction has happened, not merely a policy stated in prose.
- A change to `apps/cms`'s **own** Graphify policy (its `.graphifyignore`, its tracked-artefact list, its gate) is proposed at [`ahliweb/awcms#805`](https://github.com/ahliweb/awcms/issues/805) and arrives here through the ordinary subtree sync — never a local edit, for the same reason nothing else in `apps/cms` is locally edited (ADR-0001).
- The root graph is a navigation aid over this repository, never a source of truth: `knowledge/README.md`'s own "Working with the knowledge graph" section states — and `AGENTS.md` repeats — that every finding it surfaces must be verified against current code, tests, and contracts before anyone acts on it, and that a generated community label or a low cohesion score is a structural artefact of clustering, never by itself evidence of a design defect.
