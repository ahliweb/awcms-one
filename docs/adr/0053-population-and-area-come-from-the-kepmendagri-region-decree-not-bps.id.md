# ADR-0053 — Penduduk dan luas wilayah diambil dari Kepmendagri kode wilayah, bukan dari BPS

- **Status:** Diterima
- **Tanggal:** 11 November 2026
- **Pengambil keputusan:** ahliweb (keputusan pemilik 11 November 2026)
- **Menggantikan:** [ADR-0051](0051-bps-population-statistics-are-versioned-global-reference-data-stored-exactly-as-published.id.md)
- **Terkait:** issue [#497](https://github.com/ahliweb/awcms-one/issues/497); [ADR-0024](0024-awcms-one-is-template-only-derived-apps-own-their-backend.id.md) (kepemilikan template-only; penamaan netral); [ADR-0015](0015-commerce-migrations-live-in-the-reserved-9xx-range.id.md) (pita migrasi); repo acuan `awcms` ADR-0046 (modul `idn_admin_regions` dan dataset `cahyadsn/wilayah` yang di-vendor) dan `awcms` ADR-0052 (aktivasi dataset wilayah adalah CLI worker)

## Konteks

[ADR-0051](0051-bps-population-statistics-are-versioned-global-reference-data-stored-exactly-as-published.id.md) mengambil angka penduduk dari buku "Dalam Angka" Badan Pusat Statistik: satu publikasi per provinsi, per kabupaten/kota, dan per kecamatan, diunduh sebagai PDF lalu diekstrak tabel demi tabel. Kalimantan Tengah masuk sepenuhnya, lalu menyusul dataset dari sebagian 20 provinsi lain, sebelum pemilik menghentikan sumber ini pada 11 November 2026: "Hentikan penggunaan data dari BPS karena terlalu banyak data yang diperlukan, gunakan Permendagri saja."

Biaya jalur BPS, diukur dari pekerjaan di bawah ADR-0051:

- **Volume.** Setiap tingkat wilayah adalah publikasi tersendiri, sehingga cakupan nasional berarti puluhan ribu PDF. Pasangan CSV/JSON yang sudah ditinjau dan di-commit, 3.812 dataset dari 21 provinsi dan masih jauh dari lengkap, memakan 7.624 file dan sekitar 39 MB (sekitar 53 MB di disk), belum termasuk tooling dan fixture.
- **Akses.** Situs BPS berada di belakang Cloudflare: diblokir total dari alamat pusat data, tantangan yang tidak lolos oleh browser headless dari alamat Indonesia non-residensial, dan 403 sesaat setelah rentetan permintaan. ADR-0051 D9 melarang segala bentuk bypass, sehingga crawler hanya bisa berhenti dan menunggu.
- **Waktu.** Server unduhan BPS mengirim tiap file dengan kecepatan puluhan KB/detik; satu provinsi beserta kecamatannya butuh berjam-jam untuk diunduh, lalu langkah arsip mengunggah ulang setiap PDF ke remote di luar lokasi.
- **Kerapuhan.** Lapisan teks bertanda air, baris yang tercetak tidak berurutan, buku kecamatan berupa hasil pindai tanpa teks, dan sampul yang menyebut kecamatan lain semuanya perlu penanganan sendiri, dan 32 buku kecamatan di satu provinsi tetap tidak menghasilkan dataset.

Sementara itu, angka yang benar-benar dibutuhkan platform, per provinsi dan kabupaten/kota, sudah ada di repositori. `apps/cms/data/idn-admin-regions/` mem-vendor, dari commit hulu yang sama dengan dump wilayah yang diimpor `idn_admin_regions`, dua file pendamping yang belum dibaca apa pun:

- `db/wilayah_penduduk.sql` — header-nya: "Data jumlah penduduk dan kode wilayah sesuai Kepmendagri No 300.2.2-2138 Tahun 2025". Jumlah penduduk total, laki-laki, dan perempuan untuk 38 provinsi dan 514 kabupaten/kota, ditambah satu baris nasional: 553 baris, 34.429 byte.
- `db/wilayah_luas.sql` — "Data Kode Wilayah sesuai Kepmendagri No 300.2.2-2138 Tahun 2025" dan "Data Luas Wilayah berdasar dari Badan Informasi Geospasial … Surat Deputi Bidang Informasi Geospasial Dasar Nomor B-16.10/DIGD-BIG/IGD.04.04/12/2024, Tanggal 16 Desember 2024". Luas dalam km2 dengan tiga desimal untuk 552 wilayah yang sama: 552 baris, 26.322 byte.

Keduanya tercatat checksum-nya di `apps/cms/data/idn-admin-regions/manifest.json` dan `checksums.sha256`, dan keduanya berada di bawah keputusan menteri yang sama dengan kode wilayah yang sudah disajikan platform.

## Keputusan

**D1. BPS tidak lagi menjadi sumber, di mana pun.** Dataset hasil ekstraksi (seluruh direktori `apps/cms/data/idn-population/` beserta README dan NOTICE-nya), tooling pipeline (`tools/bps-population/`), tes dan fixture root-nya (`tests/fixtures/bps-population/` dan keempat `tests/bps-population-*.test.mjs`), serta kode khusus BPS (parser CSV `domain/population-csv.ts`, manifest per publikasi `domain/population-manifest.ts`, dan aturan sel kecil `domain/population-privacy.ts`) dihapus. Tidak ada crawler pengganti: sumber baru sudah ada di repositori.

**D2. Angkanya adalah penduduk menurut Kepmendagri dan luas menurut BIG, per provinsi dan kabupaten/kota.** `bun run idn-population:import` membaca kedua file vendor secara OFFLINE dan menulis SATU dataset dengan empat angka per wilayah: jumlah penduduk total, laki-laki (`pria`), perempuan (`wanita`), dan luas dalam km2. 552 wilayah, 2.208 angka. Baris nasional pada file penduduk tidak disimpan: `awcms_idn_admin_regions` tidak punya tingkat untuknya dan ia dapat diturunkan, sehingga importer memeriksa bahwa ia sama dengan jumlah 38 provinsi, lalu mencatatnya sebagai dilewati.

**D3. Provenans dicatat per file dan jujur.** `source_table` setiap angka menyebut file-nya, dan kolom baru `source_files` pada baris dataset mencatat, per file, path, sha256, ukuran, repositori dan commit hulu, asal angkanya, dan angka yang disumbangkannya. Jumlah penduduk diatribusikan ke Kepmendagri No 300.2.2-2138 Tahun 2025 (`figure_basis = 'decree'`). Luas diatribusikan ke Badan Informasi Geospasial dan suratnya (`figure_basis = 'geospatial_calculation'`), tidak pernah ke Kemendagri; hanya KODE wilayah pada file luas yang mengikuti Kepmendagri. Kedua file adalah kemasan komunitas (`cahyadsn/wilayah`, MIT), bukan ekspor resmi Kemendagri maupun BIG: catatan rujukan-resmi dataset wilayah (`awcms` ADR-0046) disalin ke `terms_of_use` setiap baris dataset, dan `publication_url` menunjuk commit hulu tempat file dibaca. Lisensi MIT mencakup kemasan itu, bukan angkanya.

**D4. Diverifikasi sebelum dibaca, divalidasi sebelum ditulis, gagal tertutup.** Sebelum satu angka pun dibaca, sha256 dan ukuran setiap file harus cocok dengan `manifest.json` DAN `checksums.sha256`, manifest harus menandai file itu dibaca oleh importer ini (`importedBy: idn_admin_regions.population`), dan header setiap file masih harus menyebut Kepmendagri (serta, untuk file luas, surat BIG); ketidakcocokan apa pun menolak proses dan tidak mencatat apa-apa. Dump diurai sebagai teks oleh parser ketat (`domain/population-dump-parser.ts`, aturan yang sama dengan parser wilayah ditambah pemeriksaan daftar kolom `INSERT`), tidak pernah dieksekusi. Validasi lalu melaporkan setiap masalah, dan masalah apa pun mencatat baris dataset `rejected` tanpa angka: setiap kode harus terpetakan ke provinsi atau kabupaten/kota pada dataset wilayah AKTIF dengan kedalaman yang sesuai; dataset wilayah aktif harus menyebut Kepmendagri yang sama; tidak ada kode ganda dalam satu file; `pria + wanita = total`; setiap luas positif dengan paling banyak tiga desimal; setiap wilayah tingkat 1/2 ada di kedua file; kabupaten/kota menjumlah ke provinsinya (penduduk persis, luas dalam per seribu km2 yang persis); provinsi menjumlah ke baris nasional.

**D5. Satu perbaikan, bersaksi, tercatat.** Lima baris pada file luas yang di-vendor membawa kode yang pernah melewati bilangan floating-point (`11.1` untuk `11.10`, `12.1`, `12.2`, `14.1`, dan `31.0` untuk provinsi `31`). Kode yang tidak terpetakan dibaca sebagai `NN.D0` (dari `NN.D`) atau `NN` (dari `NN.0`) hanya bila wilayah itu ada pada tingkat yang sesuai, tidak juga muncul apa adanya di file yang sama, dan nama barisnya sama dengan nama resmi wilayah itu. Setiap perbaikan tercantum di `validation_summary.codeRepairs` dan dicetak oleh perintahnya. Nama yang berbeda pada kode yang terpetakan (`Kab Timor Tengah Selatan`, `Papua Barat Oaya`) adalah peringatan; ejaan sumber disimpan sebagai `source_region_name`.

**D6. Tabel `sql/882` tetap; `sql/883` mengubah aturannya.** `apps/cms/sql/882_awcms_idn_population_stats.sql` sudah diterapkan dan tetap identik per byte. Migrasi maju baru `apps/cms/sql/883_awcms_idn_population_kepmendagri_source.sql`, nomor bebas berikutnya di pita `880`-`899` repo ini:

- menghapus setiap baris BPS (statistik dulu, lalu dataset), sehingga basis data yang pernah mengimpor angka BPS berhenti menyajikannya. Tidak ada peran yang memegang DELETE pada tabel ini; ini berjalan sebagai pemilik migrasi dan menjadi satu-satunya pengecualian yang disengaja;
- mengganti CHECK khusus BPS dengan CHECK yang menerima sumber Kepmendagri dan tidak yang lain: `source_type = 'kepmendagri_decree'`, `publication_series = 'kepmendagri_kode_data_wilayah'`, situs web `*.kemendagri.go.id` yang opsional, `publisher_domain` dan `csv_sha256` (konsep BPS) dipaksa NULL, dimensi `total`/`sex`/`area`, satuan `jiwa`/`km2`, basis `decree`/`geospatial_calculation`, universe `total_population`/`region_area`, kategori tertutup per dimensi, dan CHECK pasangan agar luas tidak pernah memakai satuan atau basis jumlah penduduk, dan sebaliknya;
- memperlebar `value` dari `numeric(14,2)` menjadi `numeric(14,3)`: BIG mencetak tiga desimal, dan membulatkan 1851,615 km2 menjadi 1851,62 berarti menyimpan angka yang tidak pernah dicetak sumbernya. Desimal keempat ditolak, tidak dibulatkan;
- menambah `source_files` (jsonb, larik tidak kosong), menjadikan kolom file tunggal `source_file_sha256`/`source_file_bytes` boleh NULL, dan menerima cakupan nasional (`coverage_region_level = 0`, `coverage_region_code = 'ID'`), sehingga indeks satu-aktif `sql/882` kini berarti satu dataset Kepmendagri yang aktif.

Hak akses tidak berubah: `awcms_app` SELECT pada kedua tabel; `awcms_worker` SELECT dan INSERT pada keduanya serta UPDATE pada tabel dataset; tidak ada yang memegang DELETE. Kedua tabel tetap global (tanpa `tenant_id`, tanpa RLS) di `GLOBAL_TABLE_FORBIDDEN_PRIVILEGES`.

**D7. Siklus hidup dan perintah ADR-0051 dipertahankan.** `validated` -> `active` -> `superseded`, dengan `rejected`; `bun run idn-population:import` (dry run secara bawaan, `--commit` menulis; kini tanpa `--dataset` atau `--all-pending`) dan `bun run idn-population:activate -- --dataset <code|uuid>` tetap dengan nama, entri registri job, dan peran `awcms_worker`-nya, dan tetap tidak menulis baris audit dengan alasan yang diberikan `awcms` ADR-0052. Kode dataset diturunkan dari Kepmendagri dan sha256 kedua file (`kepmendagri-300.2.2-2138-2025-b0b6b9dc-3ffd506e` untuk pasangan yang di-vendor), sehingga menjalankan ulang atas byte yang identik adalah no-op yang keluar dengan 0, dan koreksi yang di-vendor ulang menjadi dataset baru untuk diaktifkan. Baris `rejected` yang byte identiknya kemudian lolos (karena dataset wilayah sudah diperbaiki) dinaikkan menjadi `validated`, dengan penolakan sebelumnya disimpan sebagai `validation_summary.previousRejection`: worker tidak punya DELETE, sehingga tanpa ini byte tersebut tidak akan pernah bisa diimpor.

## Konsekuensi

- **Breaking bagi siapa pun yang pernah mengimpor angka BPS.** Setelah `bun run db:migrate`, setiap dataset dan angka BPS hilang, dan dimensi kelompok umur, agama, lapangan pekerjaan, pendapatan, dan pengeluaran, satuan `ribu_jiwa`/`rupiah`, serta angka tingkat kecamatan/desa tidak ada lagi. Tidak ada apa pun di repositori ini yang membacanya (tidak ada API dan tidak ada layar), tetapi aplikasi turunan yang membaca tabelnya langsung akan kehilangannya. Jalankan `bun run idn-population:import -- --commit` lalu `bun run idn-population:activate -- --dataset <code> --commit` untuk menyajikan angka Kepmendagri.
- Cakupannya persis cakupan Kepmendagri: provinsi dan kabupaten/kota, total dan jenis kelamin, ditambah luas dari BIG. Tidak ada angka kecamatan atau desa, umur, agama, atau pekerjaan, dan tidak ada ukuran pendapatan. Masing-masing memerlukan sumber baru dan ADR-nya sendiri.
- Aturan penekanan sel kecil ADR-0051 D7 dipensiunkan bersama kodenya: angka terkecil yang disimpan adalah jumlah penduduk satu kabupaten utuh, dan tidak tersisa rincian yang dapat menunjuk satu rumah tangga. Sumber tingkat kecamatan atau desa di masa depan harus membawa aturannya sendiri.
- Sekitar 40 MB file terlacak (7.670 file: dataset BPS, tooling, tes, dan fixture-nya) keluar dari repositori; importer membaca 60 KB yang sudah di-vendor. Tes dan tool root tidak lagi memerlukan `pdftotext`, `rclone`, `BPS_CACHE_DIR`, atau `BPS_ARCHIVE_REMOTE`.
- Angka penduduk adalah hitungan administratif sebuah Kepmendagri, bukan sensus atau proyeksi, dan tahun acuan yang disimpan adalah tahun Kepmendagri (2025) dan tahun surat BIG (2024); file tidak menyebut periode lain dan tidak ada yang ditebak.
- Divergensi lokal terhadap hulu bertambah beberapa baris dan berkurang sebanyak tooling BPS: `data/idn-admin-regions/manifest.json` (`importedBy` kedua file, `decreeReference` file penduduk yang dulu keliru dicatat tidak ada di header-nya, `areaSourceReference`, tiga catatan; tidak ada checksum atau ukuran yang berubah), tes vendor-manifest (pencocokan header kini melipat spasi, karena file penduduk membungkus rujukan Kepmendagri-nya di dua baris), dan kalimat-kalimat satu baris yang diluruskan di README modul, README data, dan `source-provenance.ts`. Semuanya tercantum di [`AGENTS.md`](../../AGENTS.id.md).

## Kandidat untuk hulu

Kapabilitas ini generik (setiap deployment AWCMS yang menyajikan wilayah Indonesia dapat memakai penduduk dan luas Kepmendagri), dan file sumbernya sudah milik hulu. Ia kandidat untuk diusulkan ke `ahliweb/awcms` bersama kedua tabel, importer, dan perubahan manifest. Bila hulu mengadopsinya, file lokal dan `sql/882`/`sql/883` dibuang pada sinkronisasi itu dengan penggantian nama ledger.

## Alternatif yang dipertimbangkan

- **Mempertahankan BPS untuk tingkat yang tidak dimiliki Kepmendagri (umur, agama, kecamatan).** Ditolak pemilik: biaya pada konteks D1 justru ada di tingkat-tingkat itu.
- **Menyimpan luas dengan dua desimal pada `numeric(14,2)` yang ada.** Ditolak: membulatkan 552 angka yang tercetak, dan importer-lah yang akan mengarangnya.
- **Dua dataset, satu per file (penduduk dari Kemendagri, luas dari BIG).** Dipertimbangkan: cocok dengan kolom file tunggal `sql/882`. Ditolak demi satu dataset dengan `source_files` per file, karena kedua file berbagi kode Kepmendagri, di-vendor dan divalidasi bersama, dan disajikan bersama; mengaktifkannya terpisah memungkinkan penduduk dan luas dari vendoring yang berbeda disajikan berdampingan.
- **Memperbaiki lima kode yang terpotong float dengan menyunting file vendor.** Ditolak: file vendor tidak pernah disunting (`awcms` ADR-0046), dan checksum-nya adalah provenansnya.
- **Mengeksekusi dump di PostgreSQL.** Ditolak dengan alasan yang sama seperti parser wilayah: SQL hulu tidak pernah dijalankan di basis data kita.
