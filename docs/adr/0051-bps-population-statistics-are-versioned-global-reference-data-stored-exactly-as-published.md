# ADR-0051 — BPS population statistics are versioned global reference data, stored exactly as published

- **Status:** Accepted
- **Date:** 26 October 2026
- **Decision maker:** ahliweb
- **Related:** issue [#497](https://github.com/ahliweb/awcms-one/issues/497) (this ADR); [ADR-0024](0024-awcms-one-is-template-only-derived-apps-own-their-backend.md) (template-only ownership; neutral naming); [ADR-0003](0003-money-is-numeric-14-2-and-crosses-the-wire-as-a-string.md) (exact numerics); [ADR-0015](0015-commerce-migrations-live-in-the-reserved-9xx-range.md) (migration bands); the reference repo `awcms` ADR-0052 (region dataset activation is a worker CLI) and its `idn_admin_regions` module (`sql/080`)

## Context

Issue #497 asks for the latest official population figures per region of the `idn_admin_regions` hierarchy (province, regency/city, district, village), by sex, age group, religion and occupation, plus a measure of income. The only source that is both official and public is the set of statistical yearbooks Badan Pusat Statistik (BPS) publishes: "Provinsi ... Dalam Angka" (provincial office), "Kabupaten/Kota ... Dalam Angka" (regency/city office) and "Kecamatan ... Dalam Angka" (district; village-level tables).

Facts verified against the real PDFs and the real sites (25-26 October 2026):

- **BPS publishes different things at different levels, on different bases.** Totals and sex come as census (SP2020), projection or population-registration (SIAK) figures; age groups are published by regency/city (and by district only in a Kecamatan yearbook); religion comes from registration data; occupation is "lapangan pekerjaan utama" from the Sakernas labour survey, a survey estimate of the employed aged 15+, not a resident count per occupation. Units differ too: provincial and regency yearbooks print **thousands of persons** with two decimals ("288,56"), village tables print persons. A four-way breakdown per village exists only in Dukcapil DKB, which needs a PKS under Permendagri 102/2019 and is out of scope.
- **BPS publishes no household income.** What exists is the Sakernas average net monthly wage of employees (provincial yearbook tables 3.2.30 by regency/city x main industry and 3.2.31 by age group) and the Susenas average per-capita monthly expenditure. The second is a welfare proxy and is not income. Minimum wages (UMK/UMP) are regulation, not a population measure.
- **The printed PDFs are imperfect.** The text layer carries a diagonal watermark interleaved with the numbers, and occasionally emits two rows' values out of order, so a value cannot be trusted without its arithmetic checks.
- **Access.** From a US data-centre address every BPS site was blocked; from an Indonesian residential address a plain HTTPS GET works; headless Chromium from a non-residential Indonesian address did not pass the Cloudflare challenge; a transient 403 appeared after a burst of requests and cleared within minutes. The download server answers HTTP 200 with a JSON error body for editions it does not have (the 2026 Kecamatan editions answered `{"status":"error","message":"Remote server error (404)."}`; the 2025 editions exist). BPS lists 34 provincial and 514 regency/city offices; the four newer Papua provinces (93-96) have no provincial office. Gaps are recorded, never filled.
- **Terms.** Each publication prints its own: "Dilarang mereproduksi dan/atau menggandakan sebagian atau seluruh isi buku ini untuk tujuan komersial tanpa izin tertulis dari Badan Pusat Statistik <Kantor>."

## Decision

**D1. Local to awcms-one, additive, neutral.** The capability is reusable by any derived application (ADR-0024), so it carries no consumer name. The migration is `apps/cms/sql/882_awcms_idn_population_stats.sql` in this repo's `880`-`899` band for local divergences to upstream-owned modules; the code is NEW `population-*` files inside the upstream `idn_admin_regions` module directory (`domain/` and `application/`), plus descriptor and registry rows. It is a candidate to propose upstream; if upstream adopts it, the local files are dropped at that sync.

**D2. Two global tables, no tenant, no RLS.** `awcms_idn_population_datasets` (one row per imported publication file: publisher, official website, catalogue/publication/ISSN numbers, URL, sha256 and size of the PDF, sha256 of the CSV, the terms verbatim, the region dataset the codes were validated against, row count, `validation_summary`) and `awcms_idn_population_stats` (one row per published figure). They are registered in `GLOBAL_TABLE_FORBIDDEN_PRIVILEGES`. Grants: `awcms_app` SELECT on both; `awcms_worker` SELECT and INSERT on both plus UPDATE on the datasets table; nobody has DELETE. Lifecycle `validated` -> `active` -> `superseded`, with `rejected` for an import that failed validation; a partial unique index allows one `active` dataset per `(publication_series, coverage_region_code)`, so a province and each of its regencies are separate publications served at once.

**D3. Values are stored exactly as published.** `value` is `numeric(14,2)` with a `unit` of `jiwa`, `ribu_jiwa` or `rupiah`; nothing is converted ("2,84 ribu" is stored as 2.84 `ribu_jiwa`, never 2840, because that would invent precision). `jiwa` must be integral and `rupiah` is allowed only for `income` and `expenditure` (CHECKs). Every row carries the `region_level` it was published at, its `reference_year` (not the publication year), `figure_basis` (`census`, `projection`, `registration`, `survey_estimate`), `universe` (`total_population`, `employed_15_plus`, `employees`, `per_capita`), `source_table`, the printed `source_page`, an optional `category_label` (the published label verbatim, at most 500 characters; the machine `category` key is at most 80) and `value_note = 'nil'` for BPS's nil symbol. A blank or "not available" cell produces **no row**. Different bases are never summed against each other. The statistics unique key includes `source_table`: each table keeps its own published totals, and a figure appearing in two tables is two rows.

**D4. Income is the Sakernas employee wage; expenditure is stored separately and is never called income.** Dimension `income` holds the average net monthly wage of employees (universe `employees`); dimension `expenditure` holds Susenas per-capita expenditure (universe `per_capita`). Both are `survey_estimate`. UMK/UMP are not stored. Sum checks never apply to averages.

**D5. Validate before writing, report gaps, never guess.** Pure functions (`domain/population-validation.ts`) check the header, enums, level-versus-code shape, integrality and duplicate keys; that every `region_code` exists in the ACTIVE region dataset at the stated level and inside the publication's coverage; and arithmetic consistency within one `(region, year, universe, unit, basis, source_table)`: sex sums to total, age groups sum to total and, per sex, to that sex's value, religions sum to total, and child regions sum to their parent. `jiwa` is exact; `ribu_jiwa` tolerates `0.005 x (parts + 1)` because every published figure is rounded to 0.01. A breach is an error and the dataset is recorded `rejected` with the problems. A check whose inputs are not all published is skipped and counted. Cross-table disagreement of the same figure within one dataset is a warning in `validation_summary`, never an error. The extractor (D8) applies the same rules before it writes a CSV.

**D6. Import and activation are operator CLIs, not HTTP.** `bun run idn-population:import -- (--dataset <code> | --all-pending) [--commit]` reads a reviewed file pair under `apps/cms/data/idn-population/datasets/` (`<code>.json` provenance + `<code>.csv` rows), verifies the CSV sha256 against the JSON, validates, and (dry run by default) writes a `validated` dataset and its rows in one transaction as `awcms_worker`; a manifest whose checksum disagrees is refused and records nothing. `bun run idn-population:activate -- --dataset <code|uuid> [--commit]` flips it to `active` and supersedes the previous active dataset of the same series and region in one transaction. Importing never changes what is served. Neither writes an `awcms_audit_events` row, for the reason `awcms` ADR-0052 gives for region datasets: that table is tenant-scoped and these are global actions no tenant permission can express; the evidence is the dataset row (`status`, `activated_at`) plus the command's output. Both are `manual` entries in the job registry, with no permission seed.

**D7. Privacy: small cells are withheld on any read surface.** The figures are public aggregates, but religion is specific personal data under UU 27/2022 at the individual level and a handful of people in a village can be identified. Cells with unit `jiwa` and value below 10 are withheld for `religion` at every level and for every dimension at `region_level` 4 (`suppressSmallCells` in `domain/population-privacy.ts`, unit-tested). It is cell-level suppression only; complementary suppression is the future API's decision. There is **no read API and no admin screen in this change**; the helper exists so the first one reuses one rule.

**D8. Attribution and licence scope.** Every dataset records `publisher_website` (an official `*.bps.go.id` host, enforced by a CHECK) and an Indonesian `attribution` sentence: the data was obtained from the official BPS office website, where the publication is downloadable free of charge by anyone. The MIT licence of the repository root covers the code, the CSV/JSON format and the tooling only; the figures remain BPS's, attributed to BPS, under each publication's own terms (copied verbatim into `terms_of_use` / `termsOfUse`, including the ban on commercial reproduction without written permission). Nothing in the repository may state that BPS figures are MIT-licensed (`apps/cms/data/idn-population/NOTICE.md`).

**D9. Pipeline tooling is root-owned and polite.** `tools/bps-population/` (Bun, argv-only spawns, English) discovers offices (`discover.ts`), downloads publications (`fetch.ts`) into a cache outside the repository (`BPS_CACHE_DIR`, default `~/.cache/awcms-bps-population`, resumable state file) and extracts tables from the PDFs with `pdftotext` (`extract/`), mapping row names to Kemendagri codes and refusing an unmatched or ambiguous name. The source PDFs are never committed. The crawler makes one request at a time with a minimum gap, backs off on 429/5xx, identifies as a normal browser, treats an HTTP 200 JSON error body as "missing" rather than as a PDF, and on a 403 or challenge stops or pauses and records it; it never uses a stealth browser, a proxy or any bypass. Publication-page requests are strictly sequential with a minimum gap; at most three PDF transfers from BPS's download server overlap, because that server sends each file slowly (tens of KB/s). After a dataset is written, `archive.ts` uploads its source PDF to an operator-chosen rclone remote (`BPS_ARCHIVE_REMOTE`; never named in the repository), verifies MD5 and size, and only then deletes the local copy; a PDF that yields no dataset is archived the same way into a separate folder, so it can be reprocessed (e.g. with OCR) without downloading it from BPS again. `pipeline.ts` chains extraction and archiving for each province the fetcher reports done.

**D10. Rollout is one province at a time, all three levels together.** A province's provincial yearbook, all its regency/city yearbooks and all its Kecamatan yearbooks are fetched, extracted, validated and archived before the next province starts; Kalimantan Tengah first, then Kemendagri code order. The 2026 editions are used; a Kecamatan yearbook whose 2026 file BPS's download server does not serve falls back to the 2025 edition, recorded as such. _Kabupaten/Kota Dalam Angka_ usually stops at district level, so village figures come almost entirely from the Kecamatan yearbooks. A dataset is a reviewed commit: the extractor's checks prove internal consistency, and a reviewer compares the cited pages against the CSV.

**D11. Registered where upstream's gates demand it.** Rows in `apps/cms/scripts/security-readiness.ts` (forbidden privileges and the worker grant map), `apps/cms/src/lib/database/work-class-registry.ts`, `apps/cms/scripts/data-lifecycle-table-coverage-check.ts` as `BOUNDED_BY_DESIGN` (the generic purge is age-only and would delete the dataset currently being served; a dataset is superseded, never purged), and `subjectData` rows in the `idn_admin_regions` descriptor (the dataset table names the operator in `created_by`/`activated_by`; the statistics table is unreachable by a data subject).

## Consequences

- Reading the figures later needs no unit guesswork: a consumer sees `ribu_jiwa` or `jiwa`, the basis and the year on every row, and cannot sum a census figure with a registration figure by accident.
- A wrong extraction cannot be activated silently: it is `rejected` or reviewed first, and the source PDF's sha256 makes a dataset re-verifiable.
- Coverage is exactly what BPS published: levels, tables and offices without a publication stay empty and are listed in each dataset's `knownGaps`.
- The upstream tests that pin registries change by one local line each (BOUNDED_BY_DESIGN cap, the CSV writer registry, the pinned job list); these are recorded as one divergence item in `AGENTS.md`.
- **Commercial use is the operator's responsibility.** The MIT licence does not extend to the figures. An operator who serves them in a commercial product must make their own assessment of, or obtain, BPS's written permission; this repository does not grant it.
- Not built, deliberately: a read API (OpenAPI) and an admin view, complementary suppression, Dukcapil DKB, and village-level data beyond the Kecamatan yearbooks that exist. Each needs its own issue.

## Alternatives considered

- **Convert everything to persons.** Rejected: invents precision; BPS rounded to two decimals of a thousand.
- **Tenant-scoped copy per tenant.** Rejected: the data is public and identical for every tenant; `awcms` ADR-0052's global-table reasoning applies.
- **An HTTP activation endpoint with a permission.** Rejected: no tenant permission can express a global action (`awcms` ADR-0052).
- **Third-party mirror (`wilayah_penduduk.sql`).** Rejected for this issue: sex only, coarse levels, not BPS.
- **Bypassing BPS's access controls to crawl faster.** Rejected: the tool stops instead.
