# ADR-0005 — Product URLs match the live site's shape: `/product/{slug}`, no trailing slash, `/products` redirects

- **Status:** Accepted
- **Date:** 15 September 2026
- **Decision maker:** ahliweb
- **Related:** [issue #5](https://github.com/ahliweb/awcms-one/issues/5), "Scope amendment: match the live site's URL shape" comment (the evidence and the trade-off table this ADR restates); [`apps/storefront/astro.config.mjs`](../../apps/storefront/astro.config.mjs); [`apps/storefront/server/penyaji.mjs`](../../apps/storefront/server/penyaji.mjs); [`docs/routing.md`](../routing.md); [`docs/kamus-data.md`](../kamus-data.md) (the slug-suffix migration constraint this decision creates)

## Context

The storefront was first built against `src/pages/[slug].astro` — one path segment, no namespace. Before that shipped, the coordinator checked the live site's own sitemap:

```
$ curl -sL https://mart.borneojek.com/sitemap.xml | grep -oE '<loc>[^<]+' | sed 's/<loc>//'
https://mart.borneojek.com/products
https://mart.borneojek.com/products?category_slug=kebutuhan-pokok-qy01
…
https://mart.borneojek.com/product/beras-5-kg-dbfc
https://mart.borneojek.com/product/jasa-jemput-kbj1

$ curl -sL -o /dev/null -w '%{http_code}\n' https://mart.borneojek.com/product/beras-5-kg-dbfc
200
```

The live site publishes product detail at `/product/{slug}` (singular, namespaced, no trailing slash) and a catalog/filter surface at `/products`. The originally planned `/{slug}` shape shares no path with either.

## Decision

Product detail publishes at `/product/{slug}` with no trailing slash — the live site's own shape, not a redesign. `/products`, with or without a query string (`?category_slug=…`), 301-redirects to `/`.

| | `/{slug}/` (as first built) | `/product/{slug}` (this decision) |
| --- | --- | --- |
| Indexed URLs, bookmarks, shared links at cutover | all break; need a permanent 301 map | preserved 1:1, no map needed |
| Collision with a future top-level page (`/tentang`, `/kontak`) | yes | none — namespaced under `/product/` |
| Cost to decide now vs. later | — | one file move + two config lines |

The cutover to a live database is increment 2, but the URL shape is decided **now**, in increment 1, because this documentation, the `Product` JSON-LD's `offers.url`, and every internal link in the storefront are written against it in the same change that builds the storefront at all — changing the shape later means changing all of those together; changing it now is one rename.

Three mechanical pieces carry the decision:

1. `src/pages/product/[slug].astro` (moved from `src/pages/[slug].astro`), with `canonicalPath` built as `` `/product/${product.slug}` `` and every internal link (catalog cards in `index.astro`, the breadcrumb) matching.
2. `astro.config.mjs`: `trailingSlash: "never"` site-wide (not a per-page opt-out, so a future page cannot silently reintroduce a trailing slash) and `build.format: "file"`, so the emitted file (`dist/client/product/{slug}.html`) and the served URL are byte-identical — no directory-index rewrite, no 301 between what is indexed and what is served.
3. `apps/storefront/server/penyaji.mjs`'s `isProductsRedirect`: one hardcoded rule, checked before the adapter's file lookup runs, 301-ing `/products` (path only, so a query string does not defeat the match) to `/`. This is **not** the generated `asal-pengalihan`-style redirect data file the sibling template family uses and issue #5's own file checklist excludes — it is a single, named rule living in the same file that already sets every other response header, for exactly one URL this app itself used to serve.

The `category_slug` query parameter such a `/products?...` URL might carry is **dropped by design, not lost by oversight**: category listing pages are not part of this slice (see [`docs/routing.md`](../routing.md) and [`docs/cms.md`](../cms.md) for what else is not built), so there is no page left for that filter to select on.

## Consequences

- **A real, load-bearing constraint on increment 2's data migration, recorded here so it is not lost:** the live slugs carry a 4-character uniqueness suffix generated by the Laravel application (`beras-5-kg-dbfc`, `jasa-jemput-kbj1`). The migration into `awcms_commerce_products.slug` **must carry those slugs verbatim, suffix included** — the CMS must not regenerate them from product names — or every URL this ADR preserves stops resolving to the product it used to. This is stated in bold in [`docs/kamus-data.md`](../kamus-data.md), where a reader building that migration would actually look.
- `docs/routing.md` documents `/products` as a redirect target, not a route, and names category listing as not built — a reader who finds `?category_slug=` in an old bookmark and expects filtering finds an explicit "not built" rather than a silent 404 or a filter that quietly does nothing.
