# AW Business Platform — Definition of Ready tracker

Tracks epic [#280](https://github.com/ahliweb/awcms-one/issues/280) toward its Definition of Ready (DoR, epic §15). **Nothing is implemented from this epic until DoR is reached** — no module, migration, OpenAPI path or scaffold. Placement of each capability is decided in [ADR-0040](adr/0040-aw-business-platform-capability-ownership-and-boundaries.md) (Accepted 8 October 2026 by owner decision O0, [#335](https://github.com/ahliweb/awcms-one/issues/335)); this page says what must exist, where it is produced, and what only the product owner can decide.

"Upstream" means `ahliweb/awcms`; "here" means this repository (`ahliweb/awcms-one`). A generic capability is specified upstream and arrives here by subtree sync; the adapters, and the cross-domain specs that name commerce, are specified here ([ADR-0024](adr/0024-awcms-one-is-template-only-derived-apps-own-their-backend.md)).

## Wave A: child issues

The decision list above gates content, not these issues: they are the work that produces the DoR artifacts. Wave A item 5 (invoice boundary) has no issue of its own because [ADR-0029](adr/0029-commerce-documents-are-separate-records-and-numbered-documents-are-immutable-order-snapshots.md) already settles it; what remains is recorded in [ADR-0040](adr/0040-aw-business-platform-capability-ownership-and-boundaries.md) D6. Each issue names the repository that will contain the work.

### A2. ahliweb/awcms: module admission for a generic `booking` domain — [ahliweb/awcms#915](https://github.com/ahliweb/awcms/issues/915)

Repo: `ahliweb/awcms`. Depends on: A1.
**Done (8 October 2026).** Merged upstream as [ahliweb/awcms#927](https://github.com/ahliweb/awcms/pull/927): [ADR-0131](https://github.com/ahliweb/awcms/blob/main/docs/adr/0131-generic-booking-module-admission.md) admits a generic `booking` module and [`awcms/booking.md`](https://github.com/ahliweb/awcms/blob/main/docs/awcms/booking.md) is the design pack (PRD-lite, state machine, ERD, permissions and RLS matrix, threat and privacy notes). Double-booking is prevented by an `EXCLUDE USING gist` constraint on allocation rows, with a concurrent-final-slot test specified as required; it has no commerce dependency. The pack records open questions O1, O2, O3, O5, O8, O9 and O12 without deciding them. These documents live upstream; they reach this repository's `apps/cms` only with the next subtree sync, which has not happened yet. Original scope: Write the admission ADR and design pack (PRD-lite, state machine, ERD, permissions and RLS matrix, adapter contract), modelled on `inventory`, `tax` and `procurement`. Must cover resource and capacity, schedule and exceptions with explicit timezone and interval semantics, holds with expiry, reservation lifecycle with append-only history, and a proven double-booking prevention strategy with the required concurrent-final-slot test. No commerce dependency. No code until the pack is accepted.

### A3. ahliweb/awcms: module admission for `hr_payroll` (workforce first, payroll second) — [ahliweb/awcms#916](https://github.com/ahliweb/awcms/issues/916)

Payroll is admitted but gated on O4, O7, at-rest encryption of payout accounts, and security and legal review. Identity is a mandatory composite-FK `profile_id` into `awcms_profiles` (the party-directory port never existed, and the ERP extension contracts were corrected), and the pack defines the `StaffAvailabilityPort` that Booking consumes. Open owner decisions: O1, O4, O5, O6, O7. These documents live upstream; they reach this repository's `apps/cms` only with the next subtree sync, which has not happened yet. Original scope: Admission ADR and design pack for employment (profile reference, never a second identity master), attendance, shift and an availability port for Booking; then the commission rule and accrual ledger; then payroll with period lock, SoD and effective-dated, jurisdiction-neutral rules. Decide the identity-reference mechanism (the party-directory port cited in upstream docs is not in this tree: to verify). State what stays out (accounting, fiscal documents). Payroll can be a later phase of the same admission.

## Keeping this page honest

Update a row's status in the same change that satisfies it, and cite the document. A row says "Partially satisfied" only with a path or ADR that exists. When the owner answers a decision, move it out of the table and into the ADR or spec that records it.
