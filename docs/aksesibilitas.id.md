# Aksesibilitas

Apa yang dilakukan `apps/storefront` untuk aksesibilitas, dan bagaimana itu diperiksa. **Baca bagian ini dulu: setiap klaim di bawah diverifikasi dengan membaca sumber secara manual — bukan dengan menjalankan axe, Lighthouse, atau alat aksesibilitas otomatis lainnya.** Tidak ada alat semacam itu yang terpasang di build aplikasi ini atau gate-nya saat ini. Di mana cakupan otomatis akan menangkap lebih banyak daripada yang bisa ditangkap pembacaan manual, kesenjangan itu nyata dan disebutkan di sini alih-alih disamarkan oleh daftar yang terdengar meyakinkan.

## Yang sudah ada

- **Skip link.** `BaseLayout.astro` me-render `<a class="skip-link" href="#konten">Lewati ke konten utama</a>` sebagai elemen focusable pertama di `<body>`, menargetkan `<main id="konten">` — pengguna keyboard atau pembaca layar bisa melompati header dan navigasi di setiap halaman. (Id target increment 1, `#main-content`, diganti nama menjadi `#konten` saat chrome bersama dibangun di issue #24 — link dan target berpindah bersama.)
- **Landmark di setiap halaman.** `<header>` (`Header.astro`), `<nav aria-label="Navigasi utama">`, `<main id="konten">`, `<footer>` (`Footer.astro`). `BaseLayout.astro` sendiri tidak me-render `<h1>` — disengaja, agar halaman di dalam `<slot />` memiliki satu-satunya `<h1>` tanpa shell bersaing dengannya.
- **Disclosure navigasi mobile yang tidak butuh JavaScript untuk buka atau tutup.** Nav mobile `Header.astro` adalah `<details>`/`<summary aria-label="Buka menu navigasi">` native — dapat dioperasikan keyboard dan diumumkan pembaca layar lewat semantik browser sendiri, bukan widget kustom.
- **`aria-live="polite"` di setiap tempat konten berubah tanpa navigasi halaman** — badge jumlah keranjang (`Header.astro`), hitung mundur flash sale (`components/katalog/Countdown.astro`), daftar wishlist (`pages/wishlist.astro`), isi pelacakan pesanan (`pages/pesanan.astro`), baris kutipan keranjang dan ringkasannya (`pages/keranjang.astro`), ringkasan tinjauan checkout (`pages/checkout.astro`), dan region umpan balik tambah-ke-keranjang di halaman produk (`role="status" data-cart-feedback"`). Ini baru di increment 2 — setiap region ini adalah pembaruan runtime lewat API commerce anonim (lihat [ADR-0007](adr/0007-cart-and-checkout-stay-static-the-browser-calls-anonymous-commerce-endpoints.id.md)), dan tidak satu pun dari region-region ini ada saat dokumen ini terakhir mendeskripsikan aplikasi yang sepenuhnya statis, tanpa tulis JavaScript.
- **Satu aturan `:focus-visible` tunggal dan global** (`apps/storefront/src/styles/global.css`) — outline 3px dengan offset 2px, diterapkan seragam alih-alih per-komponen, plus aturan `:focus` skip link sendiri yang memunculkannya ke layar.
- **Elemen `<a>` sungguhan untuk setiap kartu produk**, tidak pernah `<div>` dengan click handler — kartu bisa di-fokus keyboard dan dijangkau daftar link pembaca layar secara konstruksi.
- **JSON-LD di-escape terhadap script-breakout**, bukan sekadar formalitas — lihat [`docs/seo.md`](seo.id.md) untuk pertahanan XSS yang ditutup ini.
- **Setiap halaman keranjang/checkout/wishlist/pelacakan-pesanan membawa fallback `<noscript>` dan fallback WhatsApp untuk kasus JS-berjalan-tapi-CMS-mati** (`apps/storefront/src/lib/wa-fallback.ts`) — pembaca dengan JavaScript nonaktif, atau yang mencapai halaman saat `apps/cms` tak terjangkau, tidak pernah ditinggalkan dengan halaman yang diam-diam tidak melakukan apa pun.
- **`prefers-reduced-motion: reduce` dihormati** di `global.css`.
- **Semantik tabel pada daftar produk admin milik `apps/cms` sendiri** (`<caption>`, `scope="col"`, `data-label` untuk layout stacked responsif) — bagian dari `apps/cms`, bukan storefront ini; disebutkan di sini karena pembaca yang mencarinya jika tidak begitu akan menyimpulkan ketiadaannya dari keheningan. Lihat [`docs/cms.md`](cms.id.md).
- **Pemutar baca-nyaring bersifat tambahan, bukan pengganti teksnya** (issue #52, `apps/storefront/src/components/berita/PemutarDengar.astro`). Kontrolnya berbasis `<button>` dengan `aria-pressed` pada putar/jeda, nama aksesibel berupa kalimat penuh pada setiap tombol, target 44px, baris progres `role="status" aria-live="polite"`, dan kartunya dirender `hidden` sampai peramban terbukti punya `speechSynthesis` beserta suaranya — sehingga pembaca di peramban tanpa API itu, atau tanpa JavaScript, tidak pernah ditawari kontrol yang tidak melakukan apa-apa. Sorotan baca-bersama memakai `outline`/`box-shadow` justru supaya artikel tidak pernah bergeser di bawah pembaca yang sedang mendengarkan, dan `prefers-reduced-motion: reduce` melepas cahaya di sekelilingnya. Ini bukan pengganti aksesibilitas bagi artikelnya sendiri: teks itulah artikelnya, dan pemutar membacakan teks yang sama dengan suara bawaan perangkat pembaca.
- **Kontras warna diuji unit**, bukan sekadar dihitung dan dipercaya — `apps/storefront/tests/warna.test.ts` menegaskan setiap warna brand default melewati ambang kontras-teks WCAG AA terhadap foreground hasil hitungnya sendiri; lihat [`docs/ui-ux.md`](ui-ux.id.md) untuk `contrastingForeground()` itu sendiri.
- **Formulir OTP `/masuk` dan `/daftar`** (issue #88) memindahkan fokus ke kolom kode 6 digit begitu kolom itu muncul (`codeInput?.focus()` di `apps/storefront/src/scripts/masuk.ts`/`daftar.ts`, tepat setelah langkah itu ditampilkan) alih-alih membiarkan pengguna keyboard/pembaca layar mencari sendiri kolom yang baru terungkap. Input kode membawa `inputmode="numeric"` dan `autocomplete="one-time-code"` — keypad numerik di perangkat mobile, dan petunjuk bagi fitur autofill OTP platform (saran kode SMS iOS/Android, isi-otomatis TOTP pengelola kata sandi) bahwa kolom inilah tempat kode sekali pakai berada, meski belum ada kanal SMS (D2 milik issue #86; OTP dikirim lewat e-mail). Kedua halaman membawa region `role="status" aria-live="polite"` yang mengumumkan "kode terkirim"/error per kolom tanpa navigasi halaman, mengikuti pola keranjang/checkout di atas; jeda 60 detik tombol "Kirim ulang" hanyalah atribut `disabled` biasa plus teks hitung mundur yang terlihat, tidak pernah berupa keadaan yang tak bisa ditemukan pembaca layar.

## Yang tidak diperiksa

Tidak ada jalankan axe, tidak ada audit aksesibilitas Lighthouse, tidak ada walkthrough pembaca layar dengan teknologi bantu sungguhan (VoiceOver, NVDA, JAWS, TalkBack), dan tidak ada sesi navigasi khusus-keyboard yang dilakukan untuk dokumen ini. Progressive disclosure lima-langkah alur checkout dibaca untuk kebenaran keyboard/`aria-live`, tidak ditelusuri dengan pembaca layar.

## Belum dibangun

Uji otomatis, gate, atau langkah CI khusus-aksesibilitas apa pun untuk aplikasi ini — `bun run check` milik `apps/storefront` melakukan type-check aplikasi; ia tidak menjalankan audit aksesibilitas. Menambahkan satu (axe-core di CI, atau budget Lighthouse) adalah tindak lanjut yang masuk akal namun belum diambil.
