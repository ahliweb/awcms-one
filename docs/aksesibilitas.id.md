# Aksesibilitas

Apa yang dilakukan `apps/storefront` untuk aksesibilitas, dan bagaimana itu diperiksa. **Baca bagian ini dulu: setiap klaim di bawah kini diverifikasi oleh alat otomatis sungguhan — axe-core, dijalankan pada peramban Chromium sungguhan yang me-render build sungguhan — bukan sekadar dengan membaca sumber secara manual.** `apps/storefront/tests/e2e/aksesibilitas.e2e.ts` (issue #183) memindai setiap halaman kunci profil aktif (beranda, sebuah listing, sebuah halaman detail, `/masuk`/`/akun` di mana profil memilikinya) dengan `@axe-core/playwright`, hanya tag `wcag2a`/`wcag2aa`/`wcag21a`/`wcag21aa`, dan gagal pada pelanggaran `serious`/`critical`; `.github/workflows/e2e.yml` menjalankannya untuk ketiga profil build pada setiap push, mengunggah laporan HTML Playwright sebagai artifact (belum menjadi status check wajib — lihat komentar milik workflow itu sendiri). Setiap pelanggaran yang ditemukannya saat dokumen ini ditulis ulang telah diperbaiki dalam perubahan yang sama — lihat "Apa yang diperbaiki oleh jalankan axe" di bawah. Di mana cakupan otomatis akan menangkap lebih banyak daripada yang bisa ditangkap jalankan axe, kesenjangan itu nyata dan disebutkan di "Yang tidak diperiksa" alih-alih disamarkan oleh daftar yang terdengar meyakinkan.

## Yang sudah ada

- **Skip link.** `BaseLayout.astro` me-render `<a class="skip-link" href="#konten">Lewati ke konten utama</a>` sebagai elemen focusable pertama di `<body>`, menargetkan `<main id="konten">` — pengguna keyboard atau pembaca layar bisa melompati header dan navigasi di setiap halaman. (Id target increment 1, `#main-content`, diganti nama menjadi `#konten` saat chrome bersama dibangun di issue #24 — link dan target berpindah bersama.)
- **Landmark di setiap halaman.** `<header>` (`Header.astro`), `<nav aria-label="Navigasi utama">`, `<main id="konten">`, `<footer>` (`Footer.astro`). `BaseLayout.astro` sendiri tidak me-render `<h1>` — disengaja, agar halaman di dalam `<slot />` memiliki satu-satunya `<h1>` tanpa shell bersaing dengannya.
- **Disclosure navigasi mobile yang tidak butuh JavaScript untuk buka atau tutup.** Nav mobile `Header.astro` adalah `<details>`/`<summary aria-label="Buka menu navigasi">` native — dapat dioperasikan keyboard dan diumumkan pembaca layar lewat semantik browser sendiri, bukan widget kustom.
- **`aria-live="polite"` di setiap tempat konten berubah tanpa navigasi halaman** — badge jumlah keranjang (`Header.astro`), hitung mundur flash sale (`components/katalog/Countdown.astro`), daftar wishlist (`pages/wishlist.astro`), isi pelacakan pesanan (`pages/pesanan.astro`), baris kutipan keranjang dan ringkasannya (`pages/keranjang.astro`), ringkasan tinjauan checkout (`pages/checkout.astro`), dan region umpan balik tambah-ke-keranjang di halaman produk (`role="status" data-cart-feedback"`). Ini baru di increment 2 — setiap region ini adalah pembaruan runtime lewat API commerce anonim (lihat [ADR-0007](adr/0007-cart-and-checkout-stay-static-the-browser-calls-anonymous-commerce-endpoints.id.md)), dan tidak satu pun dari region-region ini ada saat dokumen ini terakhir mendeskripsikan aplikasi yang sepenuhnya statis, tanpa tulis JavaScript.
- **Satu aturan `:focus-visible` tunggal dan global** (`apps/storefront/src/styles/global.css`) — outline 3px dengan offset 2px, diterapkan seragam alih-alih per-komponen, plus aturan `:focus` skip link sendiri yang memunculkannya ke layar.
- **Elemen `<a>` sungguhan untuk setiap kartu produk**, tidak pernah `<div>` dengan click handler — kartu bisa di-fokus keyboard dan dijangkau daftar link pembaca layar secara konstruksi.
- **JSON-LD di-escape terhadap script-breakout**, bukan sekadar formalitas — lihat [`docs/seo.md`](seo.id.md) untuk pertahanan XSS yang ditutup ini.
- **Setiap halaman keranjang/checkout/wishlist/pelacakan-pesanan membawa fallback `<noscript>` dan fallback WhatsApp untuk kasus JS-berjalan-tapi-CMS-mati** (`apps/storefront/src/lib/wa-fallback.ts`) — pembaca dengan JavaScript nonaktif, atau yang mencapai halaman saat `apps/cms` tak terjangkau, tidak pernah ditinggalkan dengan halaman yang diam-diam tidak melakukan apa pun.
- **`prefers-reduced-motion: reduce` dihormati** di `global.css`.
- **Semantik tabel pada daftar produk admin milik `apps/cms` sendiri** (`<caption>`, `scope="col"`, `data-label` untuk layout stacked responsif) — bagian dari `apps/cms`, bukan storefront ini; disebutkan di sini karena pembaca yang mencarinya jika tidak begitu akan menyimpulkan ketiadaannya dari keheningan. Lihat [`docs/cms.md`](cms.id.md).
- **Pemutar baca-nyaring bersifat tambahan, bukan pengganti teksnya** (issue #52, `apps/storefront/src/components/berita/PemutarDengar.astro`). Kontrolnya berbasis `<button>` dengan `aria-pressed` pada putar/jeda, nama aksesibel berupa kalimat penuh pada setiap tombol, target 44px, baris progres `role="status" aria-live="polite"`, dan kartunya dirender `hidden` sampai peramban terbukti punya `speechSynthesis` beserta suaranya — sehingga pembaca di peramban tanpa API itu, atau tanpa JavaScript, tidak pernah ditawari kontrol yang tidak melakukan apa-apa. Sorotan baca-bersama memakai `outline`/`box-shadow` justru supaya artikel tidak pernah bergeser di bawah pembaca yang sedang mendengarkan, dan `prefers-reduced-motion: reduce` melepas cahaya di sekelilingnya. Ini bukan pengganti aksesibilitas bagi artikelnya sendiri: teks itulah artikelnya, dan pemutar membacakan teks yang sama dengan suara bawaan perangkat pembaca.
- **Kontras warna diuji unit**, bukan sekadar dihitung dan dipercaya — `apps/storefront/tests/warna.test.ts` menegaskan setiap warna brand default melewati ambang kontras-teks WCAG AA terhadap foreground hasil hitungnya sendiri; lihat [`docs/ui-ux.md`](ui-ux.id.md) untuk `contrastingForeground()` itu sendiri.
- **Formulir OTP `/masuk` dan `/daftar`** (issue #88) memindahkan fokus ke kolom kode 6 digit begitu kolom itu muncul (`codeInput?.focus()` di `apps/storefront/src/scripts/masuk.ts`/`daftar.ts`, tepat setelah langkah itu ditampilkan) alih-alih membiarkan pengguna keyboard/pembaca layar mencari sendiri kolom yang baru terungkap. Input kode membawa `inputmode="numeric"` dan `autocomplete="one-time-code"` — keypad numerik di perangkat mobile, dan petunjuk bagi fitur autofill OTP platform (saran kode SMS iOS/Android, isi-otomatis TOTP pengelola kata sandi) bahwa kolom inilah tempat kode sekali pakai berada, meski belum ada kanal SMS (D2 milik issue #86; OTP dikirim lewat e-mail). Kedua halaman membawa region `role="status" aria-live="polite"` yang mengumumkan "kode terkirim"/error per kolom tanpa navigasi halaman, mengikuti pola keranjang/checkout di atas; jeda 60 detik tombol "Kirim ulang" hanyalah atribut `disabled` biasa plus teks hitung mundur yang terlihat, tidak pernah berupa keadaan yang tak bisa ditemukan pembaca layar.
- **`/akun/alamat`, `/akun/pesanan`, `/akun/ulasan`** (issue #90) mengikuti konvensi S1 yang sama di seluruh halaman: tepat satu `<h1>` per halaman, elemen `<form>`/`<label>` sungguhan untuk setiap input (termasuk sepuluh kolom formulir alamat), kontrol ≥44px (aturan `akun.css` sendiri, diperluas alih-alih diduplikasi), region status `aria-live="polite"` untuk sukses/gagal async, blok `<noscript>` yang menyebut kontak fallback WhatsApp, dan fallback WhatsApp untuk kondisi JS-berjalan-tapi-CMS-tak-terjangkau pada setiap aksi submit. Rating bintang `/akun/ulasan` diumumkan lewat `aria-label="{n} dari 5 bintang"` pada seluruh rating, dengan glyph bintangnya sendiri `aria-hidden` — pembaca layar mendengar rating numerik sekali, bukan lima glyph yang ambigu.
- **`/akun/afiliasi`** (issue #93) mengikuti konvensi yang sama: satu `<h1>`, kontrol ≥44px, region `role="status" aria-live="polite"` untuk aksi gabung dan kasus `409 AFFILIATE_PROGRAM_DISABLED`, blok `<noscript>` plus fallback WhatsApp JS-berjalan-tapi-CMS-mati, dan setiap statistik dirender lewat `formatPrice` (tidak pernah aritmetika sisi-klien yang harus diturunkan ulang pembaca layar). Tombol "salin" tautan referral memakai ulang pola salin-aksesibel yang sama yang sudah didokumentasikan `docs/ui-ux.md` untuk kode voucher.
- **Sinkronisasi akun wishlist tidak pernah terdegradasi diam-diam.** Kegagalan `PUT`/`DELETE …/account/wishlist` (`apps/storefront/src/lib/wishlist-akun-sync.ts`) melaporkan dirinya lewat satu region `role="status" aria-live="polite"` bersama, seluruh-halaman (tersembunyi visual, dibuat sekali dan dipakai ulang setiap tombol hati) alih-alih melempar ke dalam click handler — keadaan visual tombol hati sendiri selalu mencerminkan tulisan LOKAL yang berhasil, bahkan saat sinkronisasi akun di baliknya gagal.
- **Penantian pembayaran gateway di `/pesanan` dan `/akun/pesanan` punya region live sendiri** (issue #112). Selagi pesanan `gateway` berstatus `pending_payment`, baris `aria-live="polite"` di samping tombol "Bayar sekarang" membaca "Menunggu konfirmasi pembayaran…" dan diperbarui menjadi "Pembayaran diterima." begitu poller 5 detik (`apps/storefront/src/lib/pesanan-poll.ts`) melihat pesanan berubah `paid` — pengguna pembaca layar diberi tahu bahwa halaman sedang menunggu, dan diberi tahu lagi begitu selesai menunggu, tanpa perlu menyadari sendiri perubahan judul status. Poller berjeda (tidak pernah mengumumkan) selagi tab tersembunyi, sehingga tidak pernah menarasikan progres yang tidak bisa dilihat pembaca.
- **Pilihan kanal WhatsApp di `/masuk`** (issue #115) adalah `<fieldset>`/`<legend>`/grup radio sungguhan, bukan sakelar bergaya — pembaca layar mendengar "Kirim kode lewat" sebagai nama grup dan "E-mail"/"WhatsApp" sebagai dua pilihannya. Memilih WhatsApp menukar field yang tampak (`hidden` dialihkan pada field alternatif, tidak pernah keduanya tampak sekaligus); field telepon memakai `type="tel"`, `autocomplete="tel"`, dan petunjuk format teks polos (`.toko-field-hint`) alih-alih hanya mengandalkan `placeholder`, yang tidak selalu diumumkan pembaca layar. `409 CHANNEL_UNAVAILABLE` memakai ulang region error `role="status" aria-live="polite"` yang sama seperti kegagalan `/masuk` lainnya.
- **Sakelar persetujuan promo di `/akun`** (issue #115) adalah `<input type="checkbox">` sungguhan di dalam `<label>` miliknya sendiri — tidak pernah `<div>` bergaya — berukuran target 44px yang sama seperti aturan milik `akun.css` sendiri. Ia tersimpan saat `change` tanpa tombol "Simpan" terpisah (perubahan status kotak centang ITU SENDIRI adalah niatnya), dikonfirmasi lewat region `role="status" aria-live="polite"` yang berbeda dari region ubah-nama, dan mengembalikan status `checked`-nya sendiri tanpa memuat ulang halaman saat gagal — pengguna pembaca layar yang mengalihkan sakelar ini mendengar konfirmasi atau kegagalan, dan pada kasus kegagalan status kontrol itu sendiri (dibacakan kembali oleh teknologi bantu) sesuai dengan apa yang baru saja diumumkan, tidak pernah diam-diam menyimpang dari apa yang sungguh dimiliki server.
- **`/akun/pesan`** (issue #115) mengikuti konvensi S1/S2/S3 yang sama sepanjang halaman: satu `<h1>`, elemen `<form>`/`<label>` sungguhan untuk formulir "Pesan baru" dan balasan, kontrol ≥44px, region `aria-live="polite"` untuk daftar baik daftar percakapan maupun thread pesan (sehingga halaman hasil baru atau balasan yang ditambahkan diumumkan), blok `<noscript>` plus fallback WhatsApp untuk kondisi JS-berjalan-tapi-CMS-down. Lencana belum-dibaca pada tiap baris percakapan memakai `aria-label`-nya sendiri ("`{n}` pesan belum dibaca") — lencana yang tampak hanyalah angka polos, yang sendirian akan ambigu bagi pembaca layar tanpa konteks tentang apa yang dihitungnya. Formulir balas pada thread tertutup sepenuhnya tidak ada di DOM (bukan sekadar `disabled`), digantikan catatan teks polos, sehingga pembaca layar tidak pernah mendarat pada kontrol yang hanya akan gagal jika dipakai.

- **Redesign 2026-09 (issue #166)'s token/primitif baru memegang batas AA yang sama walau mockup-nya sendiri tidak.** Caption milik mockup sendiri (`#94a3b8` pada 10px) tidak dirender di mana pun di aplikasi ini — setiap pill/badge/label baru memakai `--status-*-fg` di atas `--status-*-bg` minimal 12px (`--text-xs`), dan setiap pasangan status lembut dipilih agar tetap mencapai 4.5:1 terhadap latarnya sendiri di kedua skema warna (lihat tabel token `docs/ui-ux.md`). Tautan utility bar baru bertinggi minimal `44px` (`.utility-bar-inner a`, `global.css`) walau berada dalam strip gelap yang tampak ramping secara visual — bukan baris pendek milik mockup sendiri — dan kontrol `.radio-card`/`.stepper` membawa `<input type="radio">`/`<button>` asli di bawah setiap permukaan visualnya, tidak pernah `<div>` yang digayakan. `.btn`, `.pill`, `.field-label`, `.stepper`, `.radio-card`, dan `.segmented` hanyalah nama kelas baru — tidak satu pun mengubah markup atau perilaku terrender halaman mana pun di issue ini, karena belum ada halaman yang memakainya (issue #167/#168/#169 yang memakai).
- **Brand tile baru `Header.astro` bersifat `aria-hidden`** — teks `.site-brand` yang sudah ada (`identity.name`) tetap satu-satunya nama aksesibel tautan itu, sehingga pembaca layar mengumumkan nama situs persis sekali, bukan dua kali.
- **`akun-header.ts` kini memperbarui setiap elemen `[data-akun-tautan]`, bukan hanya yang pertama.** Issue #166 menambahkan elemen kedua (tautan "Akun saya" di utility bar) di samping tautan "Masuk"/akun milik header sendiri; skrip diubah dari `querySelector` ke `querySelectorAll` pada perubahan yang sama justru agar KEDUANYA tetap sinkron dengan status masuk — sebuah label "Masuk" yang basi bertahan setelah login pada salah satu dari keduanya akan menjadi regresi nyata dan senyap.

## Apa yang diperbaiki oleh jalankan axe (issue #183)

Jalankan `aksesibilitas.e2e.ts` sungguhan pertama terhadap token redesign 2026-09 menemukan empat pelanggaran kontras-warna `serious`, semuanya diperbaiki di token/komponen, bukan warna literal satu-off:

- **`--text-muted` dan token tautan biasa (`--link-color`/`--link-hover`) berada di bawah ambang AA 4,5:1** terhadap `--bg-subtle`/latar terang (4,34:1 dan 3,74–4,10:1) — digelapkan dalam hue sky/slate yang sama (komentar token milik `global.css` sendiri membawa pengukuran persisnya).
- **Label `.variant-options` terpilih memakai `--accent-primary` sebagai warna teksnya sendiri** (3,91:1 terhadap `--bg-subtle` pada 16px bold, masih teks berukuran normal menurut definisi "teks besar" WCAG) — dialihkan ke `--link-color`, token yang sudah digelapkan khusus untuk kasus ini.
- **Dua permukaan "band selalu-gelap" memakai `--accent-primary`/`--link-color` mode terang terlepas dari skema warna**: `.utility-bar-akun` (sudah membawa token `--accent-on-inverse` sendiri) dan chrome BERITA sendiri (`.bilah-utilitas__kiri` tautan mailto/`.bilah-utilitas__akun`, date bar issue #169, `berita-chrome.css`) — kedua yang terakhir kini memakai ulang `--text-on-inverse-muted`/`--accent-on-inverse`, token yang sama yang sudah dipakai bagian lain bar gelap yang sama.
- **Tombol submit formulir newsletter sidebar sama sekali tidak membawa class** (`FormBuletin.astro`), sehingga ter-render dengan latar default UA peramban sementara kartu gelapnya (`.band-inverse` milik `Sidebar.astro`) hanya me-restyle warna teksnya yang terwariskan — 1,29:1. Diberi `.btn btn--primary`, yang pasangan `--color-primary`/`--color-primary-foreground`-nya sudah diuji-unit untuk kontras AA (`apps/storefront/tests/warna.test.ts`); perbaikan kecil kedua (`global.css`'s `.band-inverse .btn--primary`) diperlukan karena aturan teks-redup generik `.band-inverse button` sendiri sebaliknya mengalahkan `.btn--primary` dari segi spesifisitas selector.

Jalankan pertama `responsif.e2e.ts` secara terpisah menangkap bug overflow horizontal sungguhan — baris rentang harga sidebar filter `/produk` secara tak sengaja ter-layout sebagai flex KOLOM (mewarisi `flex-direction: column` dari class `.filter-field` yang juga dibawa elemen yang sama), sehingga `flex: 1`/`min-width: 0` pada kedua field-nya menyusutkan TINGGI-nya, bukan lebarnya, meninggalkan tiap `<input type="number">` pada default intrinsiknya sendiri ~190px; diperbaiki dengan mendeklarasikan `flex-direction: row` secara eksplisit. Breakpoint satu-kolom `@media (max-width: 860px)` milik `katalog.css` punya bug kedua yang independen: track `1fr` polos (singkatan dari `minmax(auto, 1fr)`) menjaga minimum otomatisnya sendiri pada ukuran min-content item terbesar terlepas dari `min-width: 0` pada item — diperbaiki dengan `minmax(0, 1fr)`.

Test "klik backdrop untuk menutup" milik `iklan-popup.e2e.ts` sendiri (sudah ada sebelumnya, belum pernah dijalankan di CI sebelum issue ini) gagal karena alasan yang tidak berkaitan: reset `*, *::before, *::after { margin: 0; }` milik `global.css` mengalahkan `margin: auto` pemusatan milik stylesheet UA `<dialog>` sendiri (aturan penulis selalu mengalahkan aturan user-agent normal untuk properti yang sama, terlepas dari spesifisitas), menyematkan `.iklan-popup` maupun `dialog[data-promo-popup]` ke sudut kiri-atas viewport alih-alih memusatkannya — diperbaiki dengan menyatakan ulang `margin: auto` pada keduanya.

## Yang tidak diperiksa

Tidak ada audit aksesibilitas Lighthouse, tidak ada walkthrough pembaca layar dengan teknologi bantu sungguhan (VoiceOver, NVDA, JAWS, TalkBack), dan tidak ada sesi navigasi khusus-keyboard yang dilakukan untuk dokumen ini. Progressive disclosure lima-langkah alur checkout dibaca untuk kebenaran keyboard/`aria-live`, tidak ditelusuri dengan pembaca layar. Rule set axe-core sendiri menemukan minoritas kegagalan WCAG menurut pengakuan pengelolanya sendiri (alat otomatis umumnya hanya menangkap sekitar sepertiga masalah); konten yang hanya muncul pada `:hover`/`:focus`, dan apa pun yang tidak bisa dihitung axe dari DOM/CSSOM saja, juga tidak tercakup `aksesibilitas.e2e.ts`.

## Belum dibangun

Budget aksesibilitas Lighthouse, atau otomasi pembaca layar/khusus-keyboard apa pun — `aksesibilitas.e2e.ts` (issue #183) hanya mencakup rule set axe-core sendiri, sesuai "Yang tidak diperiksa" di atas.
