# AW Business Platform — traceability matrix (stories to tests, controls to tests)

Evidence for items 14 and 15 of the Definition of Done of epic [#280](https://github.com/ahliweb/awcms-one/issues/280), walked through in [`aw-business-platform-dod.md`](aw-business-platform-dod.md) for issue [#397](https://github.com/ahliweb/awcms-one/issues/397). Written **11 November 2026** against the tree at that date.

- **Scope.** Table A maps every user story of the [PRD](aw-business-platform-prd.md) section 6 (S1 to S4, L1 to L4, A1 to A9, P1 to P3: 20 stories) to the issue that built it and the test files that exercise it. Table B maps every control C-01 to C-41 of the [threat model](aw-business-platform-threat-model.md) section 7 to the threats it answers, its as-built status and its regression tests.
- **Honesty rule.** A test is listed only when its file exists and asserts the behaviour named; a control ID appearing in a test name was not enough, the assertion was read. Where a clause has no automated test the cell says "no automated test" and why. Nothing here is a compliance claim: the threat model is an engineering input ([section 6](aw-business-platform-threat-model.md) is for counsel).
- **Test locations.** Unit tests are `apps/cms/tests/*.test.ts`; database-gated integration tests are `apps/cms/tests/integration/*.integration.test.ts` and run against a real migrated PostgreSQL in `local-ci/check-cms` (they skip without `DATABASE_URL`); storefront tests are `apps/storefront/tests/`. Within the table, a bare file name means the same directory as its neighbours: `I:` marks an integration file, `U:` a unit file, `S:` a storefront file, `E:` a Playwright file under `apps/cms/tests/e2e/`.
- **Keeping it current.** A change that adds, removes or re-scopes a story, a control or a test that appears below updates this page in the same change. When a control moves (a deferred one is built, an operator one is signed off), change its row here first, then the DoD walkthrough. Every backticked path is checked by `bun run audit:dokumen`; the assertions are not, so re-read a test before keeping its row after a rewrite.

Tracking issues referred to below: the Booking adapter chain [#378](https://github.com/ahliweb/awcms-one/issues/378) (tables and links), [#379](https://github.com/ahliweb/awcms-one/issues/379) (gateway deposits), [#380](https://github.com/ahliweb/awcms-one/issues/380) (hold to order), [#381](https://github.com/ahliweb/awcms-one/issues/381) (cancellation and refund), [#382](https://github.com/ahliweb/awcms-one/issues/382) (reschedule and no-show), [#383](https://github.com/ahliweb/awcms-one/issues/383) (POS), [#384](https://github.com/ahliweb/awcms-one/issues/384) (loyalty earn), [#385](https://github.com/ahliweb/awcms-one/issues/385) (admin screens), [#386](https://github.com/ahliweb/awcms-one/issues/386) (storefront reads), [#389](https://github.com/ahliweb/awcms-one/issues/389) (revenue), [#390](https://github.com/ahliweb/awcms-one/issues/390) (booking segment rules), [#396](https://github.com/ahliweb/awcms-one/issues/396) (restore drill), [#437](https://github.com/ahliweb/awcms-one/issues/437) (link resources); CRM segments [#360](https://github.com/ahliweb/awcms-one/issues/360), [#361](https://github.com/ahliweb/awcms-one/issues/361), [#362](https://github.com/ahliweb/awcms-one/issues/362); redemption [#363](https://github.com/ahliweb/awcms-one/issues/363); commission [#391](https://github.com/ahliweb/awcms-one/issues/391); WhatsApp [#392](https://github.com/ahliweb/awcms-one/issues/392) and [#393](https://github.com/ahliweb/awcms-one/issues/393); customer Web Push [#430](https://github.com/ahliweb/awcms-one/issues/430) to [#432](https://github.com/ahliweb/awcms-one/issues/432).

### Gaps and findings recorded while writing this page

These are stated in the rows above and collected here so a follow-up can pick them up; none was fixed in this change (documentation only).

1. **C-02**: no latency floor on the neutral `404`, and no test of the booking code's entropy. The reference is the existing order code.
2. **C-03**: the limit is tested on the booking reads, the guest cancel, the POS lookup and segment previews, but not on the hold-create route, and no test rotates the source IP against a per-identifier OTP limit.
3. **C-32**: the own-account guard for a cashier (a cashier redeeming against their own loyalty account) has no test of its own that this review could find.
4. **C-01**: no test sends a tenant header or parameter to a storefront booking route and expects it ignored.
5. **P1**: no test asserts "no stock movement" for a service line keyed by hand at the till; **A9**: no end-to-end test with commerce off and Booking on.
6. **C-18**: there is no single test that every consumer is a no-op when its module is off.
7. The threat model's introduction (first callout) still says nothing described in it is implemented and every control status is "planned". Section 7 now points here; the callout is outside this change and should be refreshed with it.
